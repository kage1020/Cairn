## なぜ Cairn か

Minecraft の NBT/SNBT は、AI が直接扱うには効率がよくありません。バイナリ形式で、1 ブロックごとに 1 レコードを並べただけの平たい構造だからです。人や AI が建築を考えるときの単位 (壁、屋根、対称性) とも合っていません。Cairn は、**建築の意図を Minecraft のボクセルの世界に対応付ける中間言語** です。AI にとっては、建築物を「見て」「作る」ための目と手になります。

方針は **generation-first** です。NBT との完全な相互変換はあきらめ、AI が建築物を正確に生成・編集できることを最優先にします。そのため変換では意図的に情報を落とします (lossy)。持ち運べる成果物は常に Cairn のソースで、出力した NBT や schematic は特定のターゲット向けのビルド成果物です。

## こんなふうに書きます

```
@requires version>=1.20

theme medieval:
  slot wall  -> @cobblestone
  slot roof  -> @spruce_stairs

struct cottage size=9x7
  floor  mat_slot=floor
  walls  class=outer mat_slot=wall height=4
  door   side=front at=center
  window class=small side=front offset=2 y=2 size=2x2 sym=true
  roof   kind=gable mat_slot=roof overhang=1
```

```sh
cairn compile cottage.crn --edition java --target 1.21.4
```

## ステータス

Cairn は **設計段階** にあり、現在の仕様はドラフト `2026.06` です。言語仕様はオープンに設計を進めていて、リファレンスコンパイラはまだ骨組みの段階です。規範となるドキュメントは[仕様書](/ja/spec/)を、実装の計画は[開発者ガイド](/development/)を参照してください。
