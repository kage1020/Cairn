## 15.1 実装時に決めること

**来歴 (provenance) をどこに置くか。** `.crn` のヘッダか、ロックか。暫定の方針は、「`.crn` はヒントである `@intended_targets` だけを持ち、`verified` のような記録はコンパイラがロックに書く」です ([バージョンとエディション](/ja/spec/versioning-editions/))。

**逆変換で使う IR の型。** 情報の一部を欠いた状態も表せる単一の IR にするか、Intent IR と Raw Geometry IR を別の型にするか。暫定の方針は、「block-array の層は共有し、その上のメンバーの層で型を分ける」です ([アーキテクチャ](/ja/spec/architecture/))。

**旧形式の `.schematic`** (1.13 より前) は、v1 では扱いません。数値 ID の対応付けは、将来オプションとして検討する余地があります。

## 15.2 まだ検討していない話題

**座標系。** 角を原点とし `front = +z` とする今の固定を続けるか。それとも、中心を原点にする、入口を基準に向きを決める、`level id=floor2 y=4` のように階ごとにローカルな `y=0` を持つ、といった仕組みを導入するか。

**プリミティブへの昇格。** 寄棟屋根、陸屋根、方形屋根、柱、アーチ、`repeat` などを意味プリミティブに昇格させるか。判断は [評価フレームワーク](/ja/spec/evaluation/) の実験データに基づいて行います。

**内装。** `inside.front` という接頭辞で足りるのか、より上位の `room` という概念が必要なのか。また、家具を `def` のライブラリでまかなえるのか。

## 15.3 言語の進化の方針

Cairn の進化に伴う破壊的変更をどう扱うかは、まだ決めていません。選択肢は、Rust のような「エディション」の仕組み (年単位のオプトイン) か、リリースごとに CHANGELOG で告知するだけにするかです。ただし Cairn では「エディション」がすでに Java / Bedrock を指しているので、前者を採るなら別の用語が必要です。当面は後者、つまり CalVer と `@cairn` による来歴の記録で足ります。
