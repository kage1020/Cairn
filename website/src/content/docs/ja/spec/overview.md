## 1.1 目的

Minecraft の NBT/SNBT は AI が直接扱うには非効率です。バイナリであり、1 ブロック 1 レコードのフラットな
列だからです。粒度も噛み合っていません。人も AI も、個々のボクセルではなく壁・屋根・対称性で建築を
考えます。

Cairn は、AI が持つ汎用的な建築知識を Minecraft のボクセル世界と対応付ける中間言語です。AI が「見て」
「手を動かす」ための目と手にあたります。

## 1.2 アプローチ: generation-first

NBT との完全なラウンドトリップ忠実度は諦めます。最優先は AI が建築物を正確に生成・編集できることで、
そのため言語は設計上 lossy です。

逆方向 — NBT や schematic から Cairn へ — はベストエフォートです
([エコシステム連携](ecosystem-interop))。

可搬な成果物は常に **Cairn ソース** です。出力された NBT や schematic はターゲットに固定されたビルド
成果物であり、コンパイル済みバイナリに相当します ([バージョンとエディション](versioning-editions))。

## 1.3 スコープと非目標

レッドストーンは論理レベルで記述できます。信号・ゲート・接続を宣言すれば、コンパイラが合成し、配置し、
配線します ([レッドストーン](redstone))。v1 が扱うのは組み合わせ論理と、厳選した順序マクロです。任意の
状態機械や CPU の一般的な順序合成はスコープ外で、それらは Tier 0 の物理配置か `raw` に落とします。

v1 でスコープ外のものは他にもあります。

- 完全な NBT 復元 — チェストの中身、コマンドブロックなど。
- 1.13 のフラット化以前の、数値 ID の `.schematic` ファイルのインポート。
