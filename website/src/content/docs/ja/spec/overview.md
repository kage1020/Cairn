title: "1. 目的とスコープ"
---

## 1.1 目的

Minecraft の NBT/SNBT は、AI が直接扱うには効率がよくありません。バイナリ形式で、1 ブロックごとに 1 レコードを並べただけの平たい列だからです。粒度も合っていません。人も AI も、個々のボクセルではなく、壁・屋根・対称性といった単位で建築を考えます。

Cairn は、AI が持つ一般的な建築の知識を、Minecraft のボクセルの世界に対応付ける中間言語です。AI にとっては、建築物を「見て」「作る」ための目と手にあたります。

## 1.2 方針: generation-first

NBT との完全な相互変換はあきらめます。最優先するのは、AI が建築物を正確に生成・編集できることです。そのため、この言語は設計上、変換で情報を落とします (lossy)。

逆方向、つまり NBT や schematic から Cairn への変換はベストエフォートです ([エコシステム連携](/ja/spec/ecosystem-interop/))。

持ち運べる成果物は、常に **Cairn のソース** です。出力した NBT や schematic は特定のターゲット向けのビルド成果物で、プログラムでいえばコンパイル済みのバイナリにあたります ([バージョンとエディション](/ja/spec/versioning-editions/))。

## 1.3 スコープと非目標

レッドストーンは論理のレベルで記述できます。信号・ゲート・接続を宣言すれば、コンパイラが回路を合成し、配置し、配線します ([レッドストーン](/ja/spec/redstone/))。v1 が扱うのは、組み合わせ論理と、厳選した順序回路のマクロです。任意の状態機械や CPU を作るような汎用の順序回路合成はスコープ外です。そうした回路は、Tier 0 の物理配置か `raw` で書きます。

ほかにも、次のものは v1 のスコープ外です。

- チェストの中身やコマンドブロックなどの、NBT の完全な復元
- 1.13 のフラット化より前の、数値 ID を使う古い `.schematic` ファイルの取り込み
