Cairn は Minecraft の建築物を記述するための言語です。壁、屋根、窓、対称性、テーマ、レッドストーンの論理といった意図を宣言すると、ボクセルはコンパイラが解決します。ブロックステート、向き、座標計算、信号の配線、そしてビルド対象のエディションとバージョンに合った正しいブロック ID まで、コンパイラが決めます。

ケルン (cairn) は、場所の目印としてわざわざ積み上げた石のことです。Minecraft の建築物も、まさにそういうものです。この名前に、言語の考え方がそのまま表れています。

## 何を解決するか

Minecraft の NBT/SNBT は、AI が読み書きするには効率がよくありません。バイナリ形式で、1 ブロックごとに 1 レコードを持つからです。粒度も合っていません。人も AI も、建築を壁・屋根・対称性といった単位で考えます。Cairn は、AI が持つ一般的な建築の知識と、Minecraft のボクセルの世界との間をつなぎます。

持ち運べる成果物は、常に Cairn のソースです。出力した NBT や schematic は特定のターゲット向けのビルド成果物で、プログラムでいえばコンパイル済みのバイナリにあたります。新しい Minecraft のバージョンに対応するときは、NBT を変換するのではなく、**ソースを再コンパイル** します。

## あえてやらないこと

**NBT との完全な相互変換。** generation-first の方針をとるので、変換で情報が落ちるのは設計上の前提です。取り込んだ schematic は、低レベルの忠実な写しとして保持します。それを LLM が Cairn らしい書き方に引き上げ、ボクセル単位の差分 (voxel-diff) を見ながら元の建築に近づけていきます。

**状態機械や CPU のような、任意の順序回路のレッドストーンへの合成。** v1 が提供するのは、組み合わせ論理のゲートと厳選したマクロのライブラリだけです。それ以外は物理配置か、エスケープハッチの `raw` で書きます。

**1.13 より前の、数値 ID を使う `.schematic` の取り込み。** v1 は、1.13 のフラット化より前の形式に対応しません。

規範となる記述は[目的とスコープ](/ja/spec/overview/)にあります。

このサイトのページは、トップページとプレイグラウンドを除いて、すべて `cairn` にも同梱しています。内容はインストールしたリリースの時点のものです。`cairn docs` でページを一覧でき、`cairn docs ja/spec/syntax` で 1 ページを Markdown として表示できます。ネットワークは不要です。

言語モデル向けには、[`/llms.txt`](/llms.txt) がサイトの索引になっています。各ページは URL の末尾に `index.md` を付けると Markdown で取得でき、[`/llms-full.txt`](/llms-full.txt) には英語版の全ページが 1 つにまとまっています。

## ステータス

Cairn は設計段階で、現在の仕様はドラフト `2026.06` です。言語仕様はオープンに設計を進めていて、リファレンスコンパイラはまだ骨組みの段階です。そのため、いま特に役立つコントリビュートは、設計への批判、具体的な提案、実際の作例です。詳しくは [`CONTRIBUTING.md`](https://github.com/kage1020/Cairn/blob/main/CONTRIBUTING.md) を参照してください。
