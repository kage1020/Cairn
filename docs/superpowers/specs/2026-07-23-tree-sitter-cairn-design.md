# tree-sitter-cairn Design

- Status: **draft**
- Date: 2026-07-23
- Owner: `crates/cairn-lang-tree-sitter/`
- Language target: Cairn `@cairn 2026.06` (spec draft `2026.7`)
- Reference parser: [`crates/cairn-lang-core`](../../../crates/cairn-lang-core/) (`lex.rs`, `parse.rs`, `ast.rs`)

## 1. Purpose and scope

Add a full [tree-sitter](https://tree-sitter.github.io/) grammar for the Cairn
language at `crates/cairn-lang-tree-sitter/`, together with the Rust, Node.js,
and WebAssembly bindings needed to consume it from editors, GitHub linguist,
and the website playground.

**In scope**

- A `grammar.js` that parses every construct produced by `cairn-lang-core`'s
  reference lexer and parser: directives, `theme` / `struct` / `def` / `site`
  declarations, member commands, nested `level` / `room` scopes, logic
  declarations, and `assert` forms (truth tables and temporal assertions).
- An external scanner in C that emits synthetic `_indent` / `_dedent` /
  `_newline` tokens matching `cairn-lang-core::lex` (2-space indent, one level
  per step, tab-indent is an error, blank and comment-only lines do not shift
  the indent state).
- `queries/highlights.scm`, `queries/locals.scm`, `queries/injections.scm`.
- Rust, Node, and WASM bindings, published to crates.io and npm on the Cairn
  CalVer cadence.
- CI (`.github/workflows/tree-sitter.yml`) that regenerates the parser,
  runs the tree-sitter test corpus, exercises the Rust and Node bindings,
  and builds a `parser.wasm` release artifact.

**Out of scope**

- Any change to `cairn-lang-core`, `cairn-lang-lsp`, or the reference parser
  behaviour.
- Any change to the VS Code extension's TextMate grammar
  (`editors/vscode/syntaxes/cairn.tmLanguage.json`). VS Code does not natively
  consume tree-sitter grammars, so the TextMate grammar remains authoritative
  for that editor.
- Parsing `.crn.lock` files. Lock files are a separate format handled by
  `cairn-lang-core::lock` and are not the concern of this grammar.
- Replacing the reference parser inside the LSP. That is a future refactor
  that may reuse this crate, but it is not part of this design.

## 2. Design constraints

1. **Truth is the reference parser.** Where the spec (`syntax.md`) and the
   Rust reference parser disagree, the reference parser wins. The tree-sitter
   grammar and the reference parser must accept the same set of source files
   (see `examples/*.crn`).
2. **Indent-sensitive parsing via an external scanner.** tree-sitter does not
   handle Python-style indentation in the LR grammar. The C scanner mirrors
   `cairn-lang-core::lex::Lexer::scan_line_start`: exactly one `_indent`
   token per level increase, one `_dedent` per level closed on the current
   line, `_newline` at the logical end of each line, blank and comment-only
   lines skipped, tab indentation reported as an error to the parser.
3. **Bindings ship as a single crate.** Rust, Node, and WASM bindings all
   live under `crates/cairn-lang-tree-sitter/` with the standard
   `tree-sitter-<lang>` layout so npm and cargo consumers see one canonical
   package.
4. **Version tracks the Cairn CalVer bundle.** Initial release is
   `2026.7.0`, matching the current spec draft. Grammar breaks — anything
   that changes an accepted-source set or a public node name — are permitted
   only on monthly CalVer minors, following the
   [Compatibility Tiers](../../../website/src/content/docs/spec/compatibility.md)
   already used by the language itself.

not need the `tree-sitter` CLI.

## 4. Grammar rules

The rule set targets the token vocabulary in
`crates/cairn-lang-core/src/lex.rs::TokenKind` and the statement shapes in
`crates/cairn-lang-core/src/parse.rs`.

```
source_file       : directive* top_level_decl*

directive         : "@cairn" version_expr
                  | "@requires" version_expr
                  | "@intended_targets" value_list

top_level_decl    : theme_decl | struct_decl | def_decl | site_decl

theme_decl        : "theme" identifier ":" block_of<theme_body_item>
theme_body_item   : slot_binding | selector_rule
slot_binding      : "slot" identifier "->" material_ref
selector_rule     : selector ("->" attribute_list)?

struct_decl       : "struct" identifier attribute_list block_of<struct_body_item>
def_decl          : "def"    identifier attribute_list block_of<struct_body_item>
site_decl         : "site"   identifier attribute_list block_of<struct_body_item>

struct_body_item  : member_stmt
                  | nested_scope
                  | logic_decl
                  | assert_stmt

member_stmt       : member_keyword attribute_list ("->" signal_ref)?
member_keyword    : "floor" | "walls" | "door"  | "window"
                  | "roof"  | "stair" | "pressure_plate"
                  | "circuit" | "place" | "connect"

nested_scope      : ("level" | "room") attribute_list
                    block_of<struct_body_item>

logic_decl        : "logic" signal_ref "=" bool_expr

assert_stmt       : "assert" (truth_form | temporal_form)
truth_form        : "truth" "(" signal_list "->" signal_ref ")"
                    "{" truth_row (";" truth_row)* ";"? "}"
truth_row         : bit_pattern "->" bit
temporal_form     : "always" "(" temporal_expr ")"
temporal_expr     : signal_expr "->" "eventually" signal_ref
                    ("within" integer)?

attribute_list    : attribute*
attribute         : identifier "=" value
value             : integer | boolean | string
                  | size_literal | material_ref | signal_ref
                  | identifier | value_list
value_list        : "[" (value ("," value)*)? "]"

selector          : identifier ("[" attribute_list "]")?
                              ("." identifier)*     # e.g. inside.front
material_ref      : "@" identifier ("." identifier)*
signal_ref        : identifier ("." identifier)+    # sig.step, inside.front
size_literal      : integer "x" integer             # 9x7, no whitespace
bit_pattern       : /[01]+/                         # truth-table row bits
version_expr      : (">=" | "<=" | ">" | "<" | "=")? version_literal

bool_expr         : logical_or
logical_or        : logical_and ("or" logical_and)*
logical_and       : unary ("and" unary)*
unary             : "not"? primary
primary           : signal_ref
                  | boolean
                  | "(" bool_expr ")"
```

`block_of<T>` expands to `_indent T (_newline T)* _newline? _dedent`. The
external scanner injects `_indent`, `_dedent`, and `_newline` tokens.

### 4.1 Anonymous vs named nodes

- `@`, `->`, `=`, `>=`, `<=`, `>`, `<`, `[`, `]`, `(`, `)`, `{`, `}`, `,`,
  `;`, `:`, `.` are anonymous. Highlight queries capture them by their string
  literal.
- Keywords (`theme`, `struct`, `def`, `site`, `slot`, `level`, `room`,
  `logic`, `assert`, every member keyword, `or`, `and`, `not`, `truth`,
  `always`, `eventually`, `within`) are also anonymous string literals; the
  highlight query maps them to `@keyword`.
- Every rule listed above becomes a named node. Container rules
  (`argument_list`, `block`, `attribute_list`) are named for query
  ergonomics.

## 5. External scanner

`src/scanner.c` implements the tree-sitter external scanner ABI (v14 or the
version pinned by the tree-sitter CLI we install). It tracks:

- `indent_stack`: a `uint32_t` stack whose bottom sentinel is `0`, matching
  `Lexer::indent_stack` in `cairn-lang-core::lex`.
- Pending `_dedent` count for the current line (a single dedented line may
  emit multiple `_dedent` tokens).

Behaviour, mirroring `cairn-lang-core::lex`:

1. On a fresh line, count leading spaces. Tab is a hard error; the scanner
   returns without producing a token and lets the LR grammar surface an
   `ERROR` node in the tree.
2. Blank lines and comment-only lines (`#...`) do not shift the indent
   state — the scanner consumes them and continues.
3. If `spaces / 2` is greater than the top of `indent_stack` by exactly one,
   push it and emit `_indent`. A jump of more than one level is an error.
4. If it is less than the top, pop while greater and emit one `_dedent` per
   pop. If the level does not match after popping, emit `ERROR`.
5. `\n`, `\r\n`, and lone `\r` all count as one line break and produce
   `_newline`. EOF closes any remaining open indents with `_dedent` tokens.

Serialisation (for tree-sitter's incremental parsing) writes
`indent_stack.len` and the stack entries as little-endian `uint32_t`s.

## 6. Highlight queries

`queries/highlights.scm` captures (using capture names common to
`nvim-treesitter`, Zed, Helix, and GitHub):

| Capture | Node / literal |
| --- | --- |
| `@comment` | `comment` node, declared as an `extras` rule in `grammar.js` matching `/#[^\r\n]*/`; the scanner skips comment-only lines during indent counting so they do not shift the indent state, but in-line comments are picked up by the LR grammar's extras stream |
| `@keyword` | `theme`, `struct`, `def`, `site`, `slot`, `level`, `room`, `logic`, `assert`, every member keyword |
| `@keyword.directive` | `@cairn`, `@requires`, `@intended_targets` |
| `@keyword.operator` | `or`, `and`, `not`, `eventually`, `within`, `truth`, `always` |
| `@operator` | `->`, `=`, `>=`, `<=`, `>`, `<` |
| `@type` | `material_ref` |
| `@variable.parameter` | `attribute` name |
| `@variable.member` | segments after the first `.` in `signal_ref` and `inside.<side>` |
| `@constant.builtin` | `true`, `false` |
| `@string` | double-quoted strings |
| `@number` | integer, `bit_pattern` |
| `@number.special` | `size_literal` |
| `@punctuation.bracket` | `[]`, `()`, `{}` |
| `@punctuation.delimiter` | `,`, `;`, `.`, `:` |

`queries/locals.scm` binds `id=<ident>` attributes as
`@local.definition.member` and every attribute value that references an id
(`opened_by=`, `mat_slot=`, and any bare `identifier` value inside an
`attribute`) as `@local.reference`.

`queries/injections.scm` is empty for the initial release.

## 7. Bindings

### 7.1 Rust binding

- `Cargo.toml` adds `cairn-lang-tree-sitter` as a workspace member.
- `build.rs` compiles `src/parser.c` and `src/scanner.c` via the `cc` crate.
  The environment already provides MSVC 19.37 (Visual Studio 2022 Community)
  and `vswhere.exe`, which `cc-rs` discovers automatically — verified during
  brainstorming with a smoke build.
- `src/lib.rs` (crate root) exports `pub fn language() -> tree_sitter::Language`
  and re-exports the highlight query as a `pub const HIGHLIGHTS_QUERY: &str`.

### 7.2 Node binding

- `binding.gyp` compiles `src/parser.c`, `src/scanner.c`, and
  `bindings/node/binding.cc` into a Node addon.
- `bindings/node/index.js` and `index.d.ts` expose the language object under
  the module name `tree-sitter-cairn`.
- `package.json` `name` is `tree-sitter-cairn`, `main` is
  `bindings/node/index.js`.
- No prebuilt binaries. Consumers get a native build on install; the
  environments we care about (Windows with MSVC, macOS with Xcode, Linux
  with gcc/clang) all satisfy that.

### 7.3 WASM binding

- Not built by `cargo` or `pnpm install`. A separate CI job runs
  `tree-sitter build --wasm` under emscripten and attaches
  `tree-sitter-cairn.wasm` to the GitHub Release for that tag.
- The website consumes the WASM by pinning to a release URL at build time.

## 8. Version and publish

- Initial version: `2026.7.0`.
- `Cargo.toml` and `package.json` share the same version string.
- Rust publish rides the existing release-plz workflow. The crate is added
  to the release-plz configuration so the same tag drives both.
- npm publish uses a manual `workflow_dispatch` GitHub Actions job that runs
  `pnpm publish --no-git-checks --access public` on the tagged commit.
- The `parser.wasm` is uploaded to the GitHub Release attached to the
  crates.io / npm tag.
- Bumping the `@cairn` directive version accepted by the grammar is a
  separate axis. The grammar accepts any `@cairn <literal>` value at the
  syntax layer; the reference parser is responsible for range checks.

## 9. CI

`.github/workflows/tree-sitter.yml` runs on push and PR touching
`crates/cairn-lang-tree-sitter/**` or this workflow file, plus tag pushes
matching the CalVer pattern for the `wasm-build` job:

1. **generate-check** (`ubuntu-latest`): `pnpm dlx tree-sitter@<pinned>
   generate`, then `git diff --exit-code src/parser.c src/grammar.json
   src/node-types.json`. Fails the build if generated artefacts drift from
   what is committed.
2. **tree-sitter-test** (`ubuntu-latest`): `pnpm dlx tree-sitter test`
   against `test/corpus/`.
3. **rust-test** (`ubuntu-latest`, `windows-latest`, `macos-latest`):
   `cargo test -p cairn-lang-tree-sitter`. Includes the corpus-independent
   example integration test described in §10.
4. **node-smoke** (all three OSes, node 20 and 22): `pnpm install --frozen`
   inside the crate, then
   `node -e "console.log(require('./bindings/node').name)"`.
5. **wasm-build** (on tag push only, `ubuntu-latest`): emsdk setup,
   `tree-sitter build --wasm`, upload `parser.wasm` as a release asset.

`pnpm` is the workspace-wide package manager (matches `editors/vscode` and
`website`). `pnpm-lock.yaml` for the tree-sitter crate lives at its own
package root and is committed.

## 10. Test strategy

1. **tree-sitter corpus** (`test/corpus/*.txt`). One file per rule cluster:
   directives, theme, struct + members, nested scopes, redstone / logic /
   assertions, and an `errors.txt` covering tab indent, missing arrow,
   unmatched dedent, malformed truth table row.
2. **Example integration test** (Rust). Iterate `examples/*.crn` (all
   twelve: `at-side-walkway`, `cottage`, `crossbar`, `edition-fallback`,
   `l-walkway`, `redstone-door`, `roof-flat`, `roof-hip`, `roof-shed`,
   `themed-tower`, `village`, `window-walkway`), parse each, assert
   `!tree.root_node().has_error()`. This guarantees the grammar stays in
   lockstep with the reference parser on the canonical corpus.
3. **Highlight golden** (`test/highlight/cottage.ansi`). Freeze the output
   of `tree-sitter highlight examples/cottage.crn`. A change to
   `highlights.scm` requires an intentional golden update.
4. **Node smoke** (CI only, no Node test framework). Loading the module and
   asserting the language object is enough — behavioural coverage lives in
   the Rust and tree-sitter test suites.
5. Property-based cross-check with `cairn-lang-core::lex::lex` is
   **deferred**. It is the ideal future guardrail (accepted-source parity,
   rejected-source parity) but is out of scope for the initial release; the
   examples + corpus combination is enough for launch.
