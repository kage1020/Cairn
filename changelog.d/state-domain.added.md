- *(core,formats)* `E_STATE_DOMAIN` checks every property and value of a block state a member
  resolves to against the states its block takes at the pinned target: Java's from the block
  tables, Bedrock's from the canonical states its state map reads. `@oak_log[axis=q]` is refused at
  the literal, naming `x`, `y` and `z` and the nearest of them, and a member or walkway that binds
  it is not built. A pair another version of the edition takes names that version, as
  `@creaking_heart[active=true]` at Java 26.3 names 1.21.4, and a note block's
  `instrument=trumpet` at Bedrock 1.21.60, whose map follows a Java release without it, names
  1.26.60. A state lowering derives, such as a
  stair's `shape`, is checked at its member too. `cairn check --target`, `cairn compile` and the
  `buildable targets` row of `cairn info` raise it, and a `TargetRegistry` answers it through
  `state_domain`.
